# Data dictionary

## Organization and scope

| Table | Purpose |
| --- | --- |
| `users`, `roles`, `user_roles` | Active personnel, job roles, and training/approval responsibility |
| `customers`, `programs` | Customer and contractual program ownership |
| `processes` | Internal or special processes, including the relevant Nadcap commodity |
| `document_types` | Document classification, external-source flag, and default retention/review rules |

## Controlled documents

| Table | Purpose |
| --- | --- |
| `documents` | Stable master record and current released revision pointer |
| `document_revisions` | Immutable revision content identity, checksum, lifecycle, and review dates |
| `drawing_details` | Drawing-specific part, sheet, model, and design-authority metadata |
| `customer_spec_details` | Receipt, applicability review, currency, and flow-down evidence |
| `revision_approvals` | Named approval decision, time, meaning, and comments |
| `controlled_copies` | Point-of-use issue, acknowledgement, recall, and destruction status |

`content_uri` identifies the controlled file in a repository; the file itself should
not be stored as a SQLite blob. `content_sha256` detects replacement or corruption.
Access to both the database and repository must be controlled consistently.

## Change, competence, and assurance

| Table | Purpose |
| --- | --- |
| `requirements`, `document_requirement_links` | Clause-level applicability and procedure linkage |
| `change_requests`, `revision_change_links` | Reason, impact, authorization, implementation, and finding traceability |
| `revision_training_requirements` | Roles affected by a revision and training deadline policy |
| `training_assignments` | Person-level completion and evidence location |
| `audit_findings` | Internal, customer, accreditation, or regulatory findings |
| `event_log` | Append-oriented workflow evidence generated by controlled tools |
| `schema_versions` | Database migration version history |

## Status definitions

- **DRAFT** — editable working revision.
- **IN_REVIEW** — issued to reviewers; content changes should return it to draft.
- **APPROVED** — every assigned decision is approved; eligible for controlled release.
- **RELEASED** — current controlled revision at its effective date.
- **SUPERSEDED** — replaced by a newer released revision and retained as history.
- **OBSOLETE** — withdrawn without replacement and retained as history.

## Deployment controls

For production, expose task-specific stored procedures or an application service
rather than giving users direct table writes. Apply least privilege, centralized
authentication, tested backups, encryption, clock synchronization, and monitoring.
For electronic approval/signature use, validate identity, intent, record linkage,
and applicable regulatory requirements with Quality and Legal.
